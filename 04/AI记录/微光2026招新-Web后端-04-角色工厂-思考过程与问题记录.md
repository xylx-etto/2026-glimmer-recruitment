## 一、题目要求

`src/game/Main.java` 里留的 TODO：

- 通过工厂分别创建 Saber、Archer、Caster 三个角色
- 让每个角色发动攻击（调用 `attack`）
- 期待输出格式：

```
[剑士] 阿尔托莉雅 使用 Excalibur 发动攻击！
[弓兵] 卫宫 使用 Unlimited Blade Works 发动攻击！
[法师] 美狄亚 使用 Rho Aias 发动攻击！
```

`CharacterFactory` 里留的提示：

> TODO: 实现工厂方法，根据角色类型返回对应的角色对象
> 提示：如果传入未知类型，可以抛出 IllegalArgumentException

**最后那条提示是这道题的暗扣**——它反过来决定了工厂方法的参数类型只能是 `String`，理由见问题 3。

## 二、整体思路的演变

这一步比代码本身更值得记，因为后面所有的坑都源于最初的几个模糊判断。

| 阶段 | 我当时的想法 | 后来发现的问题 |
| --- | --- | --- |
| 1 | 工厂返回的是角色，那就用 `Saber saber = factory.getCharacter("Saber")` 接 | 编译期直接报「不兼容的类型」：**向下转型**不允许隐式发生 |
| 2 | 加个 `(Saber)` 强转不就完了 | 能过编译，但把「类型对不对」的检查从编译期推迟到了运行期，也丢掉了工厂 + 接口的多态意义 |
| 3 | 那干脆把参数从 `String` 换成 `CharacterType` 枚举，编译期就能挡住拼错 | 跟「传入未知类型抛 IAE」这条要求打架：**枚举参数根本表达不出"未知类型"**，这条要求会失去意义 |
| 4 | 用现成的 `CharacterType.valueOf()` 转，反正它抛的就是 IAE | `valueOf(null)` 抛的是 **NPE 不是 IAE**；而且它**区分大小写**，`Main` 里传的 `"Saber"` 会当场挂掉 |
| 5 | 提交版：签名保持 `String`，工厂里直接 `switch` 字符串，`default` 抛 `IllegalArgumentException` | ✅ 这就是 `src/game/` |
| 6 | （另试了一版）用 `CharacterType.from()` 把字符串收编成枚举再 switch，穷尽分支可以省掉 `default` | 思路更"类型安全"，但本题参数被那条要求钉死成 `String`，没提交，代码留在 `src/game2/` |

**一句话总结思路转变**：从「让调用方直接和具体类绑在一起」→「**调用方只认接口，字符串到类型这一步单独收编**」。

## 三、逐个问题记录

### 问题 1：`不兼容的类型: Character无法转换为Saber`，一次报三个错

**代码**

```java
CharacterFactory characterFactory = new CharacterFactory();
Saber saber   = characterFactory.getCharacter("Saber");    // ← 第 12 行
Archer archer = characterFactory.getCharacter("Archer");   // ← 第 13 行
Caster caster = characterFactory.getCharacter("Caster");   // ← 第 14 行
```

**报错**（实际 `javac` 输出，三个错一模一样，只是类型名不同）

```
Main.java:12: 错误: 不兼容的类型: Character无法转换为Saber
        Saber saber=characterFactory.getCharacter("Saber");
                                                 ^
Main.java:13: 错误: 不兼容的类型: Character无法转换为Archer
Main.java:14: 错误: 不兼容的类型: Character无法转换为Caster
3 个错误
```

**原因**

工厂方法的签名声明返回的是**接口**：

```java
public Character getCharacter(String characterType) {   // 返回 Character
```

而左边要的是**具体实现类**。Java 的引用类型转换规则是：

| 方向 | 例子 | 是否允许 |
| --- | --- | --- |
| 向上转型（子 → 父/接口） | `Character c = new Saber();` | ✅ 隐式完成 |
| 向下转型（父/接口 → 子） | `Saber s = someCharacter;` | ❌ 必须显式强转 `(Saber)` |

**关键点：编译器看的是「声明类型」，不是「实际 new 了谁」。** 方法签名写着返回 `Character`，编译器只知道这个对象可能是 `Saber`、`Archer`、`Caster` 里的任何一个（甚至以后新增的第四个），它不敢替你认定就是 `Saber`。所以这跟 `getCharacter("Saber")` 内部确实 `return new Saber()` 无关——**编译期不会去追方法体里的实现**。

**解决（选的是第 1 种）**

```java
// ① 用接口接收，多态调用 —— 推荐，这也正是工厂模式想要的效果
Character saber = characterFactory.getCharacter("Saber");
saber.attack();      // 运行时自动派发到 Saber.attack()

// ② 显式强转 —— 能过，但不推荐
Saber saber = (Saber) characterFactory.getCharacter("Saber");
```

为什么强转不推荐：一旦字符串和类型对不上（比如 `(Saber) getCharacter("Archer")`），编译期不报错、**运行期抛 `ClassCastException`**；而且强转成 `Saber` 之后，`saber` 就只能当剑士用，工厂 + 接口的多态意义就没了。

**收获**：接口类型的变量是「只能当接口用」的。要调用实现类特有的方法，先问自己「我是不是压根不该依赖具体类」。

### 问题 2：原代码里几处不致命但值得改的小毛病

| 位置 | 写法 | 问题 |
| --- | --- | --- |
| `CharacterFactory` | `System.out.println("未定义的角色"); throw new IllegalArgumentException();` | 错误信息用 stdout 打印，跟正常输出混在一起、调用方也捕获不到；而且异常**没带 message**，栈里只有一行光秃秃的 `IllegalArgumentException`，出问题不知道传的是什么值 |
| `CharacterType.java` | 枚举定义了但**一处都没被引用** | 定义了个"死"类型。作业提示的签名是 `String`，所以不算错，但白白浪费了枚举能带来的编译期检查 |
| `Saber`/`Archer`/`Caster` | `private String name; private String skill;` 构造器里赋了值，**但 `attack()` 里是硬编码的另一份字符串** | 字段赋了值从没被读过（IDE 会给 unused 警告）；同一份数据存了两份，改一处不生效 |

改法就一句话：**让异常自己携带信息**（`new IllegalArgumentException("未知角色类型: " + characterType)`），让字段真的被读到。

### 问题 3：「传入未知类型抛 IAE」这条要求，把枚举参数的路堵死了

**我的想法**：既然枚举能在编译期挡住拼错的字符串，那就把签名改成 `getCharacter(CharacterType type)`，更安全。

**为什么和题目要求冲突**

这条要求成立的前提是——**存在能传进来的"未知类型"**。而 `CharacterType` 类型的参数，编译器只允许传那三个常量（或者 `null`）。未知值**在源码里根本写不出来**，这条要求就成了空头支票。

于是只剩两条路：

- 想让这条要求有意义 → **参数必须保持 `String`**
- 想要枚举参数 → 这条要求退化成「传 `null` 抛 IAE」，非法输入只剩 `null` 一种（而且下面实测证明，光靠 `switch` 连这个都做不到）

**顺带一个重要发现**：用枚举实现这条要求其实是**免费**的——`valueOf` 抛的异常类型天然就是 `IllegalArgumentException`，一个 `try/catch` 都不用写。

---

### 问题 4：实测 `valueOf` 的四个反直觉行为

不猜，直接写探针跑（JDK 27 真实输出）：

| 输入 | 实际结果 |
| --- | --- |
| `T.valueOf("SABER")` | `OK: SABER` |
| `T.valueOf("Saber")` | `IllegalArgumentException: No enum constant EnumProbe.T.Saber` |
| `T.valueOf("")` | `IllegalArgumentException: No enum constant EnumProbe.T.` |
| `T.valueOf(null)` | **`NullPointerException: Name is null`** |
| `switch (null)` | **`NullPointerException`**（不是 IAE！） |

三条结论：

1. **`valueOf` 自己就抛 IAE**，未知类型的要求天然满足；
2. **但 `valueOf(null)` 抛的是 NPE**——这是最容易漏的一条，光调 `valueOf` 不满足「抛 IAE」的字面要求，必须自己兜；
3. **`valueOf` 区分大小写**，`"Saber"` 和 `"SABER"` 在它眼里是两个东西。

第 2 条还顺带说明：**想用枚举参数 + 满足要求，`switch` 前必须显式判 `null`**，因为实测 `switch (null)` 抛的是 NPE。

---

### 问题 5：大小写陷阱——直接 `valueOf` 会把 `Main` 弄挂

`Main` 里传的是 `"Saber"`（首字母大写），而枚举常量按惯例叫 `SABER`。所以**直接 `valueOf(characterType)` 必然抛异常**，题目给的调用方式当场就崩。

两条路：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| 改常量名 | 常量直接叫 `Saber` / `Archer` / `Caster` | 合法，但**违背 Java 枚举常量全大写的命名惯例**，谁看都别扭 |
| 归一化输入（**选了这个**） | `valueOf(raw.trim().toUpperCase())` | 多一层方法，但对外表现最友好 |

**为什么还要 catch 住再重抛一遍？** 不 catch 的话，用户传 `"Saber"` 收到的提示是：

```
No enum constant game2.CharacterType.SABER
```

这跟他实际输入的 `"Saber"` 对不上，反而更难排查。所以 catch 后用**原始字符串**重抛，同时用 cause 把原始异常挂上，栈信息不丢：

```java
try {
    return valueOf(raw.trim().toUpperCase());
} catch (IllegalArgumentException e) {
    throw new IllegalArgumentException("未知角色类型: " + raw, e);   // cause 保留原始栈
}
```

**收获**：异常消息是给"看日志的人"写的，要出现**他实际输入的那个值**，而不是转换之后的中间值。

### 问题 6：switch 表达式为什么可以不写 `default`

```java
return switch (type) {
    case SABER  -> new Saber();
    case ARCHER -> new Archer();
    case CASTER -> new Caster();
};
```

因为 `type` 是枚举、三个常量全覆盖，编译器认定为**穷尽**，不写 `default` 也能通过编译。这带来一个额外的好处：**以后给 `CharacterType` 加一个 `LANCER`，这个 switch 会立刻编译报错**，提醒你来补分支。

对比字符串版就直接暴露了短板——必须手写 `default`，且漏掉一个 `case` 编译器**完全不会提醒你**，只能等运行时走进 `default` 抛异常。

另外两点：

- `->` 是 **switch 表达式**（JDK 14+），整块 switch 直接当返回值，不用每个分支写 `return`，也不会像老式冒号 `switch` 那样「忘了 `break` 就穿透」；
- 用枚举参数时，那句 `System.out.println("未定义的角色")` 可以整个删掉——类型系统已经把非法值挡在编译期了。

---

### 附带 A：用 `foreach` 遍历 `CharacterType.values()`（可选的写法）

枚举天生适合 foreach。`values()` 返回常量数组，**顺序就是声明顺序**，所以下面这段和现在 `Main` 里三行手工调用的输出**完全一样**：

```java
CharacterFactory factory = new CharacterFactory();
for (CharacterType type : CharacterType.values()) {
    factory.getCharacter(type.name()).attack();
}
```

好处是以后加了 `LANCER` 常量，这个循环自动带上，不用回来改 `Main`。（`type.name()` 返回 `"SABER"` 这类常量名，扔给 `from()` 没问题。）

两个当时踩到的 foreach 坑，一并记下：

```java
// ❌ 打印的是集合本身，不是元素——循环几次就打印几次整个列表
for (var i : list) {
    System.out.println(list);      // 输出：[1, 2, 3, 4] / [1, 2, 3, 4] / …
}

// ✅ 元素是 i，不是 list
for (Integer i : list) {
    System.out.println(i);         // 输出：1 / 2 / 3 / 4
}
```

- **循环变量是"当前元素"，不是容器**；循环体里该写 `i`。变量名也建议别用 `i`（看着像下标），叫 `element` / `type` 更准确。
- `forEach(lambda)` 里**不能 `break` 跳出循环**：lambda 里的 `return` 只从这一轮返回。要在循环里 `break` / `continue`，只能用 `foreach` 语句，不能用 `list.forEach(...)`。

---

### 附带 B：`main` 少了 `public`

```java
static void main(String[] args) {      // 标准写法是 public static void main
```

在**当前环境（JDK 27）能跑**——JDK 25 起 JEP 512 放宽了入口方法的要求，不再强制 `public`。但换到 JDK 21 或更老的机器/评测机，会直接报：

```
错误: 在类 Main 中找不到主方法, 请将主方法定义为:
   public static void main(String[] args)
```

**解决**：无条件补上 `public`。这是唯一一个「在我这儿好好的、到别处就崩」的坑。

## 四、枚举版的完整代码（`src/game2/`，未提交，仅作记录）

> 提交版（`src/game/`）就是答卷 Q5 里那份：`CharacterFactory` 用 `String` 参数直接 `switch`，`default` 抛 `IllegalArgumentException("未定义的角色")`。下面是当时为了验证枚举思路另起的一版。

### `Character.java`（接口，未改语义）

```java
package game2;

/** 角色接口：调用方只依赖这个抽象，不依赖具体是剑士还是弓兵。 */
public interface Character {
    void attack();
}
```

### `CharacterType.java`（枚举 + 字符串收编）

```java
package game2;

public enum CharacterType {
    SABER,
    ARCHER,
    CASTER;

    /**
     * 把外部传进来的字符串转成枚举常量，未知类型一律抛 IllegalArgumentException。
     * 没有直接调 valueOf 而是包一层，是因为 valueOf 有三个不好用的地方：
     *   1. 区分大小写，valueOf("Saber") 会抛异常，而调用方习惯写 "Saber"；
     *   2. valueOf(null) 抛的是 NullPointerException，不是 IllegalArgumentException；
     *   3. 异常消息是 No enum constant game2.CharacterType.SABER，跟调用方实际传的串对不上。
     */
    public static CharacterType from(String raw) {
        if (raw == null) {
            throw new IllegalArgumentException("未知角色类型: null");
        }
        try {
            return valueOf(raw.trim().toUpperCase());
        } catch (IllegalArgumentException e) {
            // 带上原始字符串重新抛，同时用 cause 保留原始异常，栈信息不丢
            throw new IllegalArgumentException("未知角色类型: " + raw, e);
        }
    }
}
```

### `CharacterFactory.java`（签名保持 String，内部收编）

```java
package game2;

public class CharacterFactory {

    /**
     * @throws IllegalArgumentException 传入未知类型或 null 时抛出
     */
    public Character getCharacter(String characterType) {
        // 字符串先收编成枚举，非法输入在 from 里就已经抛 IAE 了，所以下面的 switch 不需要 default
        CharacterType type = CharacterType.from(characterType);

        // 枚举的 switch 表达式：三个常量全覆盖，编译器认定为穷尽。
        // 以后加一个 LANCER，这里会直接编译报错提醒你补分支。
        return switch (type) {
            case SABER  -> new Saber();
            case ARCHER -> new Archer();
            case CASTER -> new Caster();
        };
    }
}
```

### `Saber.java`（`Archer` / `Caster` 同构，只是文案不同）

```java
package game2;

public class Saber implements Character {
    private static final String TITLE = "剑士";
    private static final String NAME  = "阿尔托莉雅";
    private static final String SKILL = "Excalibur";

    @Override
    public void attack() {
        System.out.println("[" + TITLE + "] " + NAME + " 使用 " + SKILL + " 发动攻击！");
    }
}
```

> 相比原 `game` 包：`name` / `skill` 从「赋了值没人读」的实例字段改成真正被 `attack()` 读到的常量，顺手修掉了 unused 警告。

### `Main.java`

```java
package game2;

public class Main {
    public static void main(String[] args) {
        CharacterFactory characterFactory = new CharacterFactory();

        // 工厂的返回类型是接口 Character，所以左边必须用 Character 接收（多态）。
        // 写成 Saber saber = characterFactory.getCharacter("Saber") 是向下转型，编译期不通过。
        Character saber  = characterFactory.getCharacter("Saber");
        Character archer = characterFactory.getCharacter("Archer");
        Character caster = characterFactory.getCharacter("Caster");

        saber.attack();
        archer.attack();
        caster.attack();
    }
}
```

## 六、概念小结

| 概念 | 一句话记住 |
| --- | --- |
| 向上 / 向下转型 | 子类型 → 接口可以隐式；接口 → 子类型必须显式强转，否则「不兼容的类型」 |
| 编译期只看声明类型 | 方法返回 `Character`，编译器就当你拿到的只是个 `Character`，**它不去追方法体里 `new` 了谁** |
| 工厂 + 接口的意义 | 调用方只依赖抽象；一旦强转回具体类，多态就白搭了，还多了 `ClassCastException` 的风险 |
| `valueOf` 的三个坑 | 区分大小写、`null` 抛 NPE 而不是 IAE、异常消息里是转换后的名字不是原始输入 |
| 「抛 IAE」这条要求 | 它反过来说明签名必须是 `String`——枚举参数写不出「未知类型」；用枚举实现反而免费（`valueOf` 自带 IAE），但 `null` 要自己兜 |
| switch 表达式的穷尽性 | 枚举全覆盖即可省掉 `default`，而且**新增常量时会编译报错提醒你补分支**；字符串 switch 做不到 |
| 异常消息给谁看 | 出现**用户实际输入的那个值**（原始串），不是中间转换值；重抛时用 `cause` 保留原始栈 |
| foreach | 循环变量是「当前元素」不是容器，别写错成 `list`；`forEach(lambda)` 里不能 `break` |
| 入口方法 | 老老实实写 `public static void main`。JDK 25 起放宽了，但老环境会报「找不到主方法」 |
